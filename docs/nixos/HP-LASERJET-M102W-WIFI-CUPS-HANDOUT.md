# HP LASERJET PRO M102W — WI-FI, RESET და NIXOS/CUPS-ის გამართვა

**IT Lab · ტექნიკური ჰენდაუტი · 2026-10-23 · განახლება №2**  
**პლატფორმა:** NixOS · CUPS/IPP · HP LaserJet Pro M102w

## მიზანი და დადასტურებული შედეგი

ჰენდაუტი აღწერს რეალურ შემთხვევას: Wi-Fi-ის პარამეტრების შეცვლის შემდეგ HP M102w გადავიდა Offline-ში; Wi-Fi Direct-ით აღდგა მართვის ვებინტერფეისზე წვდომა; პრინტერი ხელახლა გახდა ხელმისაწვდომი ლოკალურ ქსელში და NixOS-იდან დაიბეჭდა სატესტო გვერდი. დამატებულია Reset-ის სარეზერვო გზები და ყველა მნიშვნელოვანი დიაგნოსტიკური ნაბიჯი.

- **სამუშაო ქსელური IP:** 192.168.100.5 (ამ კონკრეტული ინსტალაციის მისამართი).
- **მუშა CUPS რიგი:** HP_M102w.
- **მუშა URI:** ipp://192.168.100.5/ipp/print.
- **მეორე პრინტერი:** HP4103dw, URI ipp://10.6.6.7/ipp/print; მისი კავშირის პრობლემა ცალკეა.
- **დადასტურებული ფაქტი:** M102w-მა სატესტო გვერდი დაბეჭდა; რიგი მოგვიანებით ensure-printers.service-მა აღადგინა.
- **არ არის დადასტურებული:** HP4103dw-ის დავალებების გაუქმების საბოლოო შედეგი; პრინტერის სრული ან ქსელური Reset-ის რეალურად ჩატარება; საბოლოოდ არჩეული Wi-Fi სიხშირე.
- **დოკუმენტის წესია:** ცალკე აღინიშნება „შესრულდა“, „სცადეს“, „შემოთავაზებულია“ და „არ არის დადასტურებული“.

## 1. შესრულებული მოქმედებების ზუსტი ქრონოლოგია

ეს არის საუბარში დაფიქსირებული მოვლენები და არა ჰიპოთეტური, ბოლომდე გავლილი ინსტრუქცია.

1. **Reset მოითხოვეს, მაგრამ შესრულება არ დადასტურებულა.** თავდაპირველად განვიხილეთ ქსელისა და ქარხნული განულების გზები; იმ დროისთვის არც ერთი Reset-ის დასრულება არ დაფიქსირებულა.
2. **პრინტერი USB კაბელით უკვე იყო დაინსტალირებული.** USB-ით ბეჭდვის არსებობა თავისთავად არ ნიშნავს Wi-Fi ქსელთან კავშირს.
3. **Wireless ღილაკს მოკლედ დააჭირეს:** ინდიკატორი ჩაქრა; ხელახლა ჩართვისას აციმციმდა და შემდეგ მუდმივად აინთო. ეს სტაბილური უსადენო კავშირის ნიშანია, მაგრამ არ ამტკიცებს, რომ კომპიუტერი და პრინტერი ერთ LAN-ში არიან.
4. **კონფიგურაციის ფურცლის დაბეჭდვა სცადეს,** თუმცა მომხმარებლის ინფორმაციით მხოლოდ სარეკლამო/Demo გვერდი გამოვიდა. IP მისამართი ამ გზით არ დადგინდა.
5. **პრინტერის მართვის ვებგვერდში შევიდნენ და 5 GHz ქსელზე გადართვა სცადეს.** კავშირი ვერ შედგა: პრინტერი გახდა Offline და Wi-Fi ინდიკატორმა ციმციმი დაიწყო.
6. **WPS არ მუშაობდა როუტერზე.** პრინტერს USB კავშირი შენარჩუნებული ჰქონდა. გაიხსნა HP-ის აპლიკაციაც, მაგრამ Tools მიუწვდომელი აღმოჩნდა.
7. **Wi-Fi Direct კავშირი დამყარდა.** კომპიუტერი მიერთდა DIRECT-...-HP ქსელზე და გაიხსნა პრინტერის ვებინტერფეისი: http://192.168.223.1. ამით გახდა შესაძლებელი ქსელების სკანირება.
8. **სკანირებაში 5 GHz SSID-ც გამოჩნდა.** რეკომენდაცია იყო 2.4 GHz; მომხმარებლის მიერ საბოლოოდ არჩეული ზოლი საუბარში არ დაფიქსირებულა.
9. **M102w გამოჩნდა ლოკალურ ქსელში მისამართით 192.168.100.5.** NixOS-ის უკვე არსებული დეკლარაციული კონფიგურაციაში შეიცვალა მხოლოდ deviceUri-ის IP ნაწილი.
10. **შემოწმდა CUPS რიგი:** lpstat -v HP_M102w აჩვენებდა ipp://192.168.100.5/ipp/print; სატესტო ბეჭდვა რეალურად შესრულდა.
11. **აღმოჩნდა ორი M102w რიგი:** სამუშაო HP_M102w და ავტომატური HP_LaserJet_M102w_62056B (implicitclass://...). დუბლირებულ რიგში ორი დავალება იდო — №16 და №17.
12. **შესრულდა sudo lpadmin -x HP_LaserJet_M102w_62056B.** შემდგომი შემოწმებით გაქრა არა მხოლოდ დუბლირებული, არამედ HP_M102w რიგიც და ნაგულისხმევი პრინტერიც; მიზეზობრივი კავშირი ერთ ბრძანებასთან არ დადასტურებულა.
13. **შესრულდა sudo systemctl restart ensure-printers.service.** შედეგად HP_M102w დაბრუნდა, URI ისევ სწორი იყო და კვლავ გახდა ნაგულისხმევი.
14. **ცალკე HP4103dw-ზე დარჩენილი ჩანდა №13 და №15 დავალებები, სტატუსით „Connecting to printer“.** მათი გასაუქმებელი ბრძანებები მიწოდებული იყო, მაგრამ წარმატებული გაუქმების შემდგომი შედეგი საუბარში არ ჩანს.

## 2. კავშირის არქიტექტურა

პრინტერი როუტერის Wi-Fi ქსელით იღებს ლოკალურ IP მისამართს. NixOS-ის CUPS უკავშირდება პრინტერს IPP-ით. Wi-Fi Direct სხვა კავშირია: კომპიუტერი უშუალოდ პრინტერს უკავშირდება და ეს არ ნიშნავს, რომ პრინტერი უკვე როუტერის ქსელშია.

სქემა: NixOS → ლოკალური ქსელი/როუტერი → 192.168.100.5:631 → HP M102w.

### Wireless ღილაკი და ინდიკატორები

- **Wireless ღილაკზე მოკლე დაჭერა** რთავს ან თიშავს უსადენო ფუნქციას. სწორედ ასე გაქრა და კვლავ დაბრუნდა ინდიკაცია ამ შემთხვევაშიც.
- **ინდიკატორი მუდმივად ანათებს:** უსადენო კავშირი სტაბილურია; მაინც გადაამოწმე IP/SSID და ქსელის ხელმისაწვდომობა.
- **ინდიკატორი ციმციმებს:** შეიძლება მიმდინარეობდეს WPS ან Wi-Fi Direct დაყენება; **სწრაფი ციმციმი** მიუთითებს უსადენო კავშირის პრობლემაზე. მარტო ციმციმი კონკრეტულ მიზეზს არ ადგენს.
- **Attention (!) და Ready ინდიკატორები** განსხვავებულად გამოიყენება დიაგნოსტიკისა და Reset-ის დროს. არ აურიო Wireless და Resume/Cancel (ქვედა X/ფურცლის სიმბოლო).
- **კონფიგურაციის გვერდი (HP-ის სახელმძღვანელო):** მზადყოფნის რეჟიმში დააჭირე Resume/Cancel-ს და გეჭიროს, სანამ Ready ინდიკატორი არ დაიწყებს ციმციმს; შემდეგ აუშვი. ამ შემთხვევაში რეალურად დაბეჭდილი ფურცელი იყო Demo, ამიტომ ეს გზა საჭირო ინფორმაციის მისაღებად ვერ გამოდგა.
- **IP-ის ალტერნატიული მოძებნა:** EWS/Network Summary, როუტერის DHCP Client List ან IPP/მიმდინარე CUPS URI. Demo ფურცელი ქსელის კონფიგურაციის გვერდის ტოლფასი არ არის.


პრინტერისთვის რეკომენდებული იყო **2.4 GHz** ქსელი: მოწყობილობისთვის მაღალი გამტარობა საჭირო არ არის, ხოლო დაფარვა, როგორც წესი, უკეთესია. საბოლოოდ არჩეული ზოლი არ დაფიქსირებულა. 5 GHz SSID-ის სკანირებაში გამოჩენა თავისთავად წარმატებული დაკავშირების გარანტია არ არის. კომპიუტერი შეიძლება 5 GHz-ზე იყოს, პრინტერი — 2.4 GHz-ზე, თუ ორივე ერთსა და იმავე მარშრუტიზებად ლოკალურ ქსელშია და კლიენტთა იზოლაცია არ უშლის ხელს.

## 3. Wi-Fi Reset და Factory Reset — განსხვავებები

**ეს გზები დოკუმენტირებულია, მაგრამ საუბარში მათი შესრულება არ დადასტურებულა.** უკვე გამართული პრინტერისთვის ზედმეტი Reset საჭირო არ არის. განულებამდე ჩაიწერე SSID, IP, პაროლები, პრინტერის ქსელური პარამეტრები და NixOS-ზე მითითებული URI.

### 3.1. ქსელის/უსადენო პარამეტრების აღდგენა (Wireless Reset)

HP-ის მხარდაჭერის ფორუმზე უშუალოდ **M102w** მოდელისთვის აღწერილია ასეთი მეთოდი:

1. პრინტერი უნდა იყოს ჩართული და Ready/Power ინდიკატორი მუდმივად ანათებდეს; საჭიროების შემთხვევაში Resume/Cancel-ით გამოაღვიძე.
2. **Wireless** ღილაკს გეჭიროს დაახლოებით **20 წამი**.
3. როდესაც **Power/Ready და Attention** ინდიკატორები ერთად აციმციმდება, ღილაკი აუშვი და დაელოდე გადატვირთვას.
4. ამის შემდეგ თავიდან მოაწყვე Wi-Fi ქსელი (HP აპლიკაციით ან, თუ ხელმისაწვდომია, EWS-ით/Wi-Fi Direct-ით).

ეს ინსტრუქცია HP Support Community-ის მოდელზე ორიენტირებული პასუხიდანაა, ხოლო ქვემოთ მოცემული Factory Reset-ის EWS გზა HP-ის ოფიციალურ სახელმძღვანელოშია. **არ აურიო ხანგრძლივი Wireless დაჭერა მოკლე დაჭერაში**, რომელიც უბრალოდ Wi-Fi ფუნქციას რთავს/თიშავს.

### 3.2. სრული Factory Reset — ოფიციალური EWS მეთოდი

**HP LaserJet Pro M101–M104 User Guide, გვერდი 73:**

1. გახსენი პრინტერის Embedded Web Server (EWS) ქსელური IP-ით ან HP Device Toolbox-ით, თუ USB-თან შესაბამისი სრული HP პროგრამა მუშაობს.
2. გადადი **System → Save and Restore**.
3. განყოფილებაში **Restore Defaults** აირჩიე **Restore defaults**.
4. პრინტერი ავტომატურად გადაიტვირთება.

**გაფრთხილება:** განულდება პრინტერისა და ქსელის პარამეტრები, და შეიძლება წაიშალოს პრინტერის მეხსიერებაში შენახული გვერდები; სახელმძღვანელოს მიხედვით გვერდების მთვლელი, უჯრის ზომა და ენა ამით არ ნულდება. ქსელის ხელახლა გამართვის შემდეგ შესაძლოა IP შეიცვალოს და NixOS-ის deviceUri-ის განახლება გახდეს საჭირო.

### 3.3. სრული Factory Reset — ფიზიკური ღილაკებით

HP Support Community-ის **M102w**-ზე HP-ის თანამშრომლის 2025 წლის პასუხის თანახმად:

1. გამორთე პრინტერი.
2. ერთდროულად გეჭიროს **Wireless** და **Cancel (X)** ღილაკები.
3. ორივეს დაჭერისას ჩართე პრინტერი.
4. გააგრძელე დაჭერა დაახლოებით **10–15 წამი**, ვიდრე **Attention** ინდიკატორი არ აციმციმდება.
5. აუშვი ღილაკები და დაელოდე გადატვირთვას.

ეს არის HP მხარდაჭერის ფორუმის პასუხი და არა ზემოთ მოყვანილი ოფიციალური სახელმძღვანელოს Factory Reset-ის პროცედურა. როდესაც EWS ხელმისაწვდომია, **უპირატესობა მიანიჭე 3.2 პუნქტში დოკუმენტირებულ გზას**. არ გამოიყენო სრული Reset მხოლოდ იმიტომ, რომ CUPS-ის რიგში გაჭედილი დავალებაა — ასეთ დროს გააუქმე დავალება.

### 3.4. Reset-ის შემდეგ შემოწმება

1. განაახლე პრინტერის Wi-Fi კავშირი და გადაამოწმე მუდმივად ანთებული Wireless ინდიკატორი.
2. როუტერში მოძებნე ახალი IP, ან გადაამოწმე EWS-ში.
3. NixOS-ზე შეადარე CUPS URI პრინტერის აქტუალურ IP-ს: lpstat -v HP_M102w.
4. საჭიროების შემთხვევაში შეცვალე მხოლოდ deviceUri, გაააქტიურე დეკლარაციული კონფიგურაცია და დაბეჭდე სატესტო გვერდი.
5. **DHCP Reservation** კარგი პრევენციული გადაწყვეტილებაა, მაგრამ ამ დიალოგში მისი შესრულება არ დადასტურებულა.

## 4. USB/Windows გზა და WPS-ის შეზღუდვა

1. **USB-ით დრაივერის დაყენება** პრინტერს Windows-ში ამატებს, მაგრამ როუტერის Wi-Fi-ს ავტომატურად არ აკავშირებს.
2. HP-ის სრული პროგრამის არსებობისას **HP Printer Assistant → Device Setup & Software** (ან შესაბამისი shortcut) შეიძლება შეიცავდეს „Convert a USB connected printer to wireless“ ფუნქციას. HP-ის სახელმძღვანელოში აღწერილია USB-დან უკაბელო კავშირზე შეცვლის ეს გზა.
3. **ამ შემთხვევაში:** HP აპლიკაცია იხსნებოდა, მაგრამ **Tools მიუწვდომელი იყო**. ეს რეალური შეზღუდვა იყო, ამიტომ სამუშაო გზად გამოვიყენეთ Wi-Fi Direct + EWS და არა Windows-ის Assistant.
4. HP-ის სახელმძღვანელოში USB-ისათვის **Print → HP Device Toolbox**-ის საშუალებით EWS-ის გახსნაცაა აღწერილი, თუმცა ფუნქციების ხელმისაწვდომობა დამოკიდებულია სრული პროგრამის დაყენებასა და კავშირის ტიპზე.
5. **WPS** როუტერზე არ მუშაობდა; ამიტომ WPS-ის მეთოდი პრაქტიკულად არ შესრულებულა და სავალდებულო არც იყო.
6. **5 GHz-ზე გადართვის მცდელობა** წარუმატებელი აღმოჩნდა. საწყისი აღდგენისთვის რეკომენდებული იყო **2.4 GHz**, მაგრამ საბოლოო Wi-Fi ზოლი არ არის დაფიქსირებული; სკანირებაში 5 GHz-ის გამოჩენა მის წარმატებულ გამოყენებას არ ნიშნავს.
7. თუ Windows-ზე ქსელური პრინტერის დამატებას შეეცდები, USB და ქსელური რიგები ერთმანეთისგან გაარჩიე. საბოლოო შემოწმება USB-ის გამორთვის შემდეგ რეალური ბეჭდვაა.

## 5. Wi-Fi კავშირის აღდგენა WPS-ის გარეშე

1. დატოვე პრინტერი ჩართული; საჭიროების შემთხვევაში USB კაბელიც შეიძლება დარჩეს შეერთებული. ამ შემთხვევაში Wi-Fi Direct გზა რეალურად იმუშავა მაშინ, როცა HP აპლიკაციაში Tools მიუწვდომელი იყო.
2. კომპიუტერი დაუკავშირე პრინტერის Wi-Fi Direct ქსელს (სახელი იწყება DIRECT-...-HP).
3. ბრაუზერში გახსენი http://192.168.223.1 — Wi-Fi Direct ქსელის მართვის მისამართი **ამ კონფიგურაციაში**. ეს მისამართი ჩვენს შემთხვევაში რეალურად გაიხსნა; ის არ არის როუტერის მიერ მინიჭებული ჩვეულებრივი IP.
4. ვებინტერფეისის Networking / Wireless Configuration განყოფილებაში აირჩიე როუტერის შესაფერისი SSID (ამ შემთხვევისთვის რეკომენდებული იყო **2.4 GHz**) და შეიყვანე მისი პაროლი.
5. შეინახე პარამეტრები. დაელოდე, სანამ Wi-Fi ინდიკატორი მუდმივად აინთება.
6. კომპიუტერი დააბრუნე ჩვეულებრივ ლოკალურ ქსელში; შეამოწმე პრინტერის მიმდინარე IP მისამართი.
7. არ აურიო Direct მისამართი (192.168.223.1) როუტერის მიერ მინიჭებულ მისამართში (აქ: 192.168.100.5).

თუ დაკავშირება არ შედგა, გადაამოწმე SSID, პაროლი, როუტერის 2.4 GHz ქსელის ჩართვა, Wi-Fi-ის უსაფრთხოების რეჟიმთან თავსებადობა და ქსელის იზოლაციის პარამეტრები. WPS სავალდებულო არ არის.

## 6. NixOS-ის დეკლარაციული კონფიგურაცია

**მაგალითის ფაილი:** /etc/nixos/configuration.nix ან ამ ფაილიდან იმპორტირებული შესაბამისი მოდული.

ქვემოთ მოცემულია ამ შემთხვევის სამუშაო კონფიგურაცია. იგი განსაზღვრავს HP_M102w-ს; HP4103dw ამ ბლოკში არ არის განსაზღვრული და უკვე არსებული ცალკე რიგის სახით რჩება.

~~~nix
{ config, pkgs, ... }:
{
  services.printing = {
    enable = true;
    drivers = [
      pkgs.hplip
      pkgs.cups-filters
    ];
  };

  services.avahi = {
    enable = true;
    nssmdns4 = true;
    openFirewall = true;
  };

  # ეს ჩანაწერი არსებობდა სამუშაო კონფიგურაციაში.
  # მხოლოდ პრინტერთან გამავალი IPP კავშირისთვის საჭირო არ არის.
  networking.firewall.allowedTCPPorts = [ 631 ];

  hardware.printers = {
    ensureDefaultPrinter = "HP_M102w";
    ensurePrinters = [
      {
        name = "HP_M102w";
        location = "Wi-Fi";
        deviceUri = "ipp://192.168.100.5/ipp/print";
        model = "everywhere";
        ppdOptions.PageSize = "A4";
      }
    ];
  };
}
~~~

**შენიშვნები:**
- model = "everywhere" ამ მოწყობილობასთან პრაქტიკულად შემოწმდა სატესტო ბეჭდვით.
- hardware.printers.ensurePrinters არ შლის სხვა, სიაში არჩაწერილ CUPS რიგებს.
- hardware.printers.ensureDefaultPrinter ადგენს ნაგულისხმევ რიგს.
- networking.firewall.allowedTCPPorts = [ 631 ]; ხსნის შემომავალ TCP პორტს NixOS-ზე; ჩვეულებრივი გამავალი IPP ბეჭდვისთვის აუცილებელი არ არის. თუ CUPS-ის გაზიარება არ გამოიყენება, მისი საჭიროება ცალკე გადააფასე.
- თუ ეს მხოლოდ არსებული configuration.nix-ის ნაწილია, გარე { ... } და განმეორებითი პარამეტრები არ ჩასვა მეორედ.

## 7. აქტივაცია და შემოწმება

კონფიგურაციის შენახვის შემდეგ:

~~~bash
sudo nixos-rebuild switch
ping -c 3 192.168.100.5
lpstat -v
lpstat -p -d
~~~

მოსალოდნელი არსებითი ნიშნებია:

~~~text
device for HP_M102w: ipp://192.168.100.5/ipp/print
printer HP_M102w is idle
system default destination: HP_M102w
~~~

**Idle** ნიშნავს, რომ CUPS-ის რიგი მზადყოფნის მდგომარეობაშია, მაგრამ რეალურ ბეჭდვას არ ამტკიცებს. აუცილებელია ტესტი:

~~~bash
echo "NixOS HP M102w Wi-Fi test" | lp -d HP_M102w
~~~

ამ შემთხვევის ტესტი წარმატებით დაიბეჭდა.

თუ რიგი წაიშალა ან ცვლილების შემდეგ აღარ ჩანს, არსებული დეკლარაციული კონფიგურაციის აღსადგენად:

~~~bash
sudo systemctl restart ensure-printers.service
lpstat -v
lpstat -p -d
~~~

რეალურ შემთხვევაშიც ამ ბრძანების შემდეგ HP_M102w აღდგა და ნაგულისხმევად განისაზღვრა. სერვისის შეცდომების ნახვა შეიძლება შემდეგნაირად:

~~~bash
systemctl status ensure-printers.service --no-pager
journalctl -u ensure-printers.service -n 50 --no-pager
~~~

## 8. დუბლირებული პრინტერის რიგი

ქსელის ავტომატურმა აღმოჩენამ შეიძლება შექმნას დამატებითი CUPS რიგი. ამ შემთხვევაში გამოვლინდა:

~~~text
HP_LaserJet_M102w_62056B → implicitclass://HP_LaserJet_M102w_62056B/
HP_M102w                → ipp://192.168.100.5/ipp/print
~~~

პირველი ავტომატური/შუალედური რიგის სახით ჩანდა; მეორე — დეკლარაციულად განსაზღვრული, უკვე გამოცდილი რიგი.

დუბლირების შესაძლო წყაროა cups-browsed. თუ პრინტერებს სრულად ხელით/დეკლარაციულად მართავ, ავტომატური რიგების გენერაციის გამოსართავად შეიძლება დაამატო:

~~~nix
services.printing.browsed.enable = false;
~~~

ეს **არჩევითი ცვლილებაა** და ამ დიალოგში მისი საბოლოო გამოყენება არ შემოწმებულა. Avahi-ს ჩართვა ავტომატური CUPS რიგების შექმნისგან განსხვავებული ფუნქციაა.

რიგის წაშლამდე ნახე, აქვს თუ არა დავალებები:

~~~bash
lpstat -o HP_LaserJet_M102w_62056B
~~~

მხოლოდ დარწმუნების შემდეგ, რომ რიგი ზედმეტია და დავალებები საჭირო არ არის:

~~~bash
sudo lpadmin -x HP_LaserJet_M102w_62056B
~~~

**გაფრთხილება:** lpadmin -x შლის პრინტერის რიგს, არა მხოლოდ მის დავალებებს. ამ რეალურ შემთხვევაშიც შემდგომი შემოწმებისას HP_M102w რიგიც აღარ ჩანდა; ზუსტი მიზეზი დადგენილი არ არის. სამუშაო რიგი აღდგა ensure-printers.service-ით. ნუ მიაწერ ავტომატურად ყველა ცვლილებას ერთ კონკრეტულ ბრძანებას — მდგომარეობა გადაამოწმე.

## 9. ბეჭდვის დავალებების უსაფრთხო გასუფთავება

მიმდინარე დავალებების სანახავად:

~~~bash
lpstat -o
~~~

ამ შემთხვევის HP4103dw რიგში გამოვლინდა დავალებები HP4103dw-13 და HP4103dw-15, რომლებიც შეცდომით იყო გაშვებული. **გაუქმების ბრძანებები მიწოდებულია, თუმცა შესრულების შემდგომი lpstat -o შედეგი საუბარში არ ჩანს.**

მხოლოდ ამ ორი დავალების გაუქმება:

~~~bash
sudo cancel HP4103dw-13 HP4103dw-15
~~~

ან ამ კონკრეტულ პრინტერზე **ყველა** დავალების გაუქმება:

~~~bash
sudo cancel -a HP4103dw
~~~

დადასტურება:

~~~bash
lpstat -o
lpstat -p -d
~~~

თუ lpstat -o ცარიელია, მიმდინარე რიგში აღარ ჩანს მოლოდინში/აქტიური დავალებები. **ეს შემოწმება აუცილებლად შეასრულე თავად:** დასკვნა წინასწარ არ უნდა გამოვიტანოთ. cancel არ შლის პრინტერის კონფიგურაციას. ამისგან განსხვავებით, lpadmin -x საერთოდ შლის რიგს.

## 10. ტიპური შეცდომები და დიაგნოსტიკა

- **Wi-Fi ინდიკატორი ციმციმებს:** შეიძლება მიმდინარეობდეს WPS/Wi-Fi Direct კონფიგურაცია; სწრაფი ციმციმი შეიძლება მიუთითებდეს კავშირის პრობლემაზე. ჯერ დააზუსტე მიმდინარე რეჟიმი და მხოლოდ შემდეგ მოიძიე მიზეზი.
- **Wi-Fi Direct მუშაობს, მაგრამ ბეჭდვა Offline-ია:** Direct-ით მართვა და როუტერის LAN-ით IPP ბეჭდვა სხვადასხვა გზებია.
- **printer HP4103dw ... Connecting to printer:** რიგი არსებობს, მაგრამ შესაბამის ქსელურ კავშირს ვერ ამყარებს; შეამოწმე IP, მარშრუტი და TCP 631.
- **ორი ქვექსელი:** 192.168.100.x და 10.6.6.x ერთმანეთს მხოლოდ შესაბამისი მარშრუტიზაციის პირობებში მიაღწევენ.
- **zsh: command not found: device:** lpstat-ის შედეგის სტრიქონი (device for ...) შეცდომით შეყვანილია როგორც ბრძანება.
- **no system default destination:** გადაამოწმე ensureDefaultPrinter და საჭიროების შემთხვევაში ხელახლა გაუშვი ensure-printers.service.
- **პრინტერი Idle-ია, მაგრამ არ ბეჭდავს:** განასხვავე რიგის სტატუსი, IPP-ის ხელმისაწვდომობა, დრაივერი და რეალური სატესტო გვერდი.

დამატებითი ქსელური შემოწმება მეორე პრინტერზე:

~~~bash
ip route get 10.6.6.7
ping -c 3 10.6.6.7
curl -v --connect-timeout 3 http://10.6.6.7:631/
~~~

HTTP ფესვისთვის მიღებული 404/405 პასუხი თავისთავად არ ადასტურებს IPP endpoint-ის მუშაობას ან გაუმართაობას.
